# Context Engine — Setup Guide

Everything needed to go from a fresh clone to a fully working system. Written so an AI agent on the other side can follow this unambiguously.

## Step-by-step setup

### 1. Clone

```bash
git clone https://github.com/Usmansayed/new-context-engine.git
cd new-context-engine
```

### 2. Python environment

**Recommended — uv:**

```bash
# Install uv once: https://docs.astral.sh/uv/getting-started/installation/
uv venv
source .venv/bin/activate          # Linux / macOS
# .\.venv\Scripts\Activate.ps1   # Windows PowerShell

uv pip install -e ".[dml]"         # Windows GPU: dml | NVIDIA: cuda | Mac: coreml | CPU: cpu
```

**Alternative — venv + pip:**

```bash
# Linux / macOS
python3 -m venv .venv
source .venv/bin/activate

# Windows PowerShell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
```

### 3. Install all packages

**uv (recommended):**

```bash
uv pip install -e .
uv pip install "mcp>=1.0,<2" psutil
```

**pip:**

```bash
pip install -e .
pip install "mcp>=1.0,<2"
pip install psutil
```

This gives you:
- All core dependencies (numpy, faiss-cpu, tree-sitter grammars, networkx, requests, rapidfuzz, huggingface_hub)
- The MCP server library
- Resource monitoring (psutil)
- CLI commands: `ctx` and `ctx-mcp`

### 4. Install GPU acceleration + download embedding model

This is the critical step that gets the ~270MB FP16 embedding model and the right ONNX Runtime.

#### Automatic (recommended — works on all OS):

```bash
ctx init
```

What this does:
1. Detects your hardware:
   - NVIDIA GPU → selects `cuda` profile
   - AMD/Intel GPU on Windows → selects `dml` profile (DirectML)
   - No GPU or Linux AMD → selects `cpu` profile
2. Uninstalls any conflicting ONNX Runtime wheels
3. Installs the correct wheel:
   - cuda: `onnxruntime-gpu>=1.17`
   - dml: `onnxruntime-directml>=1.17`
   - cpu: `onnxruntime>=1.17`
4. Installs `fastembed>=0.4`
5. Downloads `nomic-ai/CodeRankEmbed` **FP16** ONNX (`onnx/model_fp16.onnx`, ~270MB) from HuggingFace
   - Cached at `~/.cache/fastembed/` (Linux/Mac) or `%TEMP%\fastembed_cache\` (Windows)
   - FP32 `model.onnx` is not used in production
6. Runs a microbenchmark (target: 10 texts/sec)
7. Saves profile to `~/.context-engine/accel.json`

#### Force a specific profile:

```bash
ctx init --profile cuda    # NVIDIA with CUDA toolkit
ctx init --profile dml     # Windows AMD/Intel/NVIDIA via DirectML (no CUDA needed)
ctx init --profile cpu     # Any OS, no GPU
```

#### If ctx init fails — manual install:

```bash
# Step 1: Install FastEmbed (uv recommended)
uv pip install "fastembed>=0.4" "huggingface_hub>=0.20"
# or: pip install fastembed>=0.4 huggingface_hub>=0.20

# Step 2: Remove all ORT wheels (they conflict with each other)
uv pip uninstall onnxruntime onnxruntime-gpu onnxruntime-directml
# or: pip uninstall -y onnxruntime onnxruntime-gpu onnxruntime-directml

# Step 3: Install ONE of these:
uv pip install "onnxruntime>=1.17"              # CPU (any OS)
uv pip install "onnxruntime-gpu>=1.17"          # NVIDIA CUDA
uv pip install "onnxruntime-directml>=1.17"     # Windows DirectML

# Step 4: Download the model
python -c "from fastembed import TextEmbedding; m = TextEmbedding('nomic-ai/CodeRankEmbed'); list(m.embed(['warmup']))"
```

#### Alternative: SentenceTransformers backend (heavier, PyTorch-based):

```bash
pip install sentence-transformers>=3.0 torch einops
# Set env: CTX_EMBED_BACKEND=coderank
```

### 5. Get the test data

The `testdata/` directory is gitignored. You need `testdata/frontend-mcp/` to run experiments.

**Option A — Get from team (fastest):**

Ask another team member for a zip/tar of `testdata/frontend-mcp/`. Extract into:
```
new-context-engine/testdata/frontend-mcp/
```

It should contain ~2681 files across these top-level directories:
```
coordination_layer/
design_benchmarks/
docs/
evals/
execution_layer/
packages/
references/
research/
sandbox/
scripts/
src/
tests/
vendor/
.github/
```

Key files the experiments check for:
- `**/agent_guidance.py`
- `**/browser_session_manager.py`
- `**/dispatch_registry.py`

**Option B — If there's an internal repo:**
```bash
mkdir testdata
git clone <internal-frontend-mcp-repo-url> testdata/frontend-mcp
```

### 6. Set up environment variables

```bash
cp .env.example .env
```

Edit `.env` with your keys. Only needed for running live A/B experiments:

```
GOOGLE_GENERATIVE_AI_API_KEY=your-gemini-key-here
GEMINI_API_KEY=your-gemini-key-here
```

For **local-only usage** (indexing, searching, serving), no API keys are required. The system is fully local.

### 7. Generate the .cursor config (if using Cursor IDE)

```bash
ctx setup --repo .
```

Or manually create `.cursor/mcp.json`:

```json
{
  "mcpServers": {
    "context-engine": {
      "command": "<absolute-path-to-.venv>/python",
      "args": ["-u", "-m", "pipeline.mcp_locate"],
      "env": {
        "PYTHONPATH": "<absolute-path-to-repo>/packages",
        "CTX_REPO": "<absolute-path-to-target-repo>",
        "CTX_ENGINE_URL": "http://127.0.0.1:8765",
        "CTX_RETRIEVE": "D_channel_best",
        "CTX_TOKEN_MODE": "savings",
        "CTX_BACKGROUND_SYNC": "1",
        "CTX_ALLOW_BG_FULL": "0",
        "CTX_AUTO_INDEX": "1",
        "CTX_SYNC_INTERVAL_MS": "300000",
        "CTX_REGISTRATION_MODE": "automatic",
        "PYTHONUTF8": "1"
      }
    }
  }
}
```

And `.cursor/rules/context-agent.mdc`:
```markdown
---
description: Context Engine — default locate; Grep is rare
alwaysApply: true
---

# Context Engine (CE) = your default code locate

Tools: `search` | `read` | `status`.
Use CE instead of Grep for almost all discovery. Grep is rare.

Need → do this:
- Soft / unfamiliar / "where|how|who" → `search(query)` — NEVER Grep first
- After search hits → ALWAYS `read(target)` before edit
- Exact literal ONLY after two thin searches → Grep once (≤2 Greps/task)

Flow: `search` → `read` → edit → test.
```

### 8. Index a repository and start the engine

```bash
# Index the test corpus (or any repo)
ctx engine start testdata/frontend-mcp

# This will:
# 1. Start the daemon on http://127.0.0.1:8765
# 2. Register the project
# 3. Run full index (graphify → chunk → embed → FAISS)
# 4. Start the watchdog sidecar
# 5. Start the background sync loop (keeper)
```

Wait for it to report healthy. First index of frontend-mcp takes ~2-5 minutes depending on GPU.

Verify:
```bash
ctx engine status
# Should show: warm_state=ready, chunks=~3148

ctx search "where is agent guidance for session errors" testdata/frontend-mcp
# Should return hits including agent_guidance.py
```

### 9. Install OpenCode (for A/B experiments only)

```bash
npm install -g opencode-ai
opencode --version
# Should print something like 1.18.x
```

Configure a model provider. Create `~/.config/opencode/opencode.json`:
```json
{
  "provider": {
    "google-ai-studio": {
      "apiKey": "your-gemini-key"
    }
  }
}
```

### 10. Run tests

```bash
# Unit tests (no testdata or daemon needed for most)
pytest tests/ -x -q

# Quick smoke test that engine works
ctx search "authentication" .
```

## Full verification checklist

After setup, all of these should work:

```bash
# 1. CLI works
ctx --help

# 2. Accel is configured
ctx init --status
# Should show: profile=dml/cuda/cpu, model=nomic-ai/CodeRankEmbed

# 3. Engine starts and indexes
ctx engine start testdata/frontend-mcp
ctx engine status
# warm_state=ready, chunks > 0

# 4. Search works
ctx search "session disappeared guidance" testdata/frontend-mcp
# Returns hits with agent_guidance.py

# 5. MCP server starts
python -m pipeline.mcp_locate
# Should print: [context_engine_mcp] surface=read tools=search,read,status
# (Ctrl+C to kill — it reads from stdin)

# 6. Tests pass
pytest tests/ -x -q --ignore=tests/seir_exp

# 7. Dry-run experiment works
.venv/Scripts/python -u scripts/experiments/opencode_raw_vs_ce/run.py --dry-run
# (Linux: .venv/bin/python ...)
```

## Per-OS notes

### Windows

- Python from python.org or Microsoft Store works. Avoid Anaconda (conflicts with ORT wheels).
- DirectML (dml profile) works on AMD, Intel, and NVIDIA GPUs without installing CUDA.
- Use PowerShell, not CMD. Activate: `.\.venv\Scripts\Activate.ps1`
- If DML batch size causes OOM on small GPUs (e.g. RX 6500M 4GB), set `CTX_EMBED_BATCH=8`.

### macOS

- No DirectML. Use `cpu` profile (or `embed-st` extra with MPS if you want PyTorch).
- Apple Silicon works with the cpu profile (ONNX Runtime ARM64 build).
- `brew install python@3.11` if system Python is too old.

### Linux

- NVIDIA: Install CUDA toolkit 12.x first, then `ctx init --profile cuda`.
- AMD (ROCm): Not directly supported by ONNX Runtime. Use `cpu` profile or the SentenceTransformers backend with `torch` (ROCm build).
- CPU-only: `ctx init --profile cpu` — works everywhere, just slower embedding.

## Stopping / cleanup

```bash
# Stop the engine and watchdog
ctx engine stop

# Kill stuck processes (if engine stop fails)
# Windows:
taskkill /F /IM python.exe    # nuclear option — kills all python

# Linux/Mac:
pkill -f "pipeline engine run"

# Remove all local state (to start fresh)
rm -rf ~/.context-engine/
```

## Troubleshooting

| Problem | Fix |
|---------|-----|
| `ModuleNotFoundError: pipeline` | Activate venv and run from repo root |
| `No index found` | Run `ctx index <path>` or `ctx engine start <path>` |
| `engine.lock held by pid X` | `ctx engine stop` then retry |
| `onnxruntime` import error | Only ONE ORT wheel allowed. `pip list \| grep onnx`, uninstall extras |
| DML OOM on small GPU | Set `CTX_EMBED_BATCH=8` in environment |
| Embedding very slow (<1 t/s) | Check `ctx init --status` — may be on CPU accidentally |
| `testdata/frontend-mcp` missing | Get from team — experiments won't run without it |
| psutil warnings | `pip install psutil` |
| `mcp` import fails | `pip install "mcp>=1.0,<2"` |
| MCP not connecting in Cursor | Settings → MCP → refresh. Check paths in `.cursor/mcp.json` are absolute |
| pytest import errors | Run from repo root with venv active. `pytest.ini` handles pythonpath |
| OpenCode experiments timeout | Increase timeout in run.py or check that daemon is warm (`ctx engine status`) |
