# Sessions learning

A durable record of every harness run so we can learn from each one and keep improving the
Scubiee map **tool**, its **rules**, and its **instructions**. This folder is the single place
to look before making another tuning change.

## What's here

| File | What it is | How to refresh |
|---|---|---|
| `VERSIONS.md` | **Full reference for every Scubiee/map variant** (what it is, tool surface, rules, bridge file, performance). The key to the `arm` field. Read this first. | hand-written |
| `extract_sessions.py` | Walks every run dir under `.ab_workspaces/claude_sdk_harness/`, normalises each cell (dev-task + retrieval schemas) into one flat record. | `python docs/sessions-learning/extract_sessions.py` |
| `data/sessions.jsonl` | One JSON object per cell — the machine-readable dataset (124 cells and counting). | regenerated by the extractor |
| `SESSIONS_LOG.md` | Human-readable, run-by-run log: arm, task, tokens, calls, oracle, and the tool sequence. | regenerated by the extractor |
| `mine_patterns.py` | Aggregate signals we tune on (per-arm cost, head-to-head, find follow-up rate, config usage, retrieval recall/precision). | `python docs/sessions-learning/mine_patterns.py` |
| `PATTERNS.md` | The mined patterns table — evidence base for every rule/tool change. | regenerated by the miner |
| `mine_call_purposes.py` + `CALL_PURPOSES.md` | Classifies every call by purpose (locate/read/wire/grep) to show WHERE calls go and what a better tool could collapse. | `python docs/sessions-learning/mine_call_purposes.py` |
| `mine_trajectories.py` + `TRAJECTORIES.md` | Trajectory shapes, grep-fallback penalty, cost-vs-calls correlation, winning vs losing move. | `python docs/sessions-learning/mine_trajectories.py` |
| `TOOL_DESIGN_STUDY.md` | Session-grounded study of what tools would save the most tokens (led to map_v3). | hand-written |
| `RESEARCH_REPORT.md` | Research report + fine-tuning plan from the sessions (consistency check, cost law, change list). | hand-written |
| `LEARNINGS.md` | The distilled patterns (P1-P9) + the rule/instruction/tool changes they justify. The thing to read after VERSIONS. | hand-written, cites PATTERNS.md |

## Workflow for the next tuning cycle

1. Run arms (`run_dev_mini.py`) — the cells land under `.ab_workspaces/claude_sdk_harness/`.
2. `python docs/sessions-learning/extract_sessions.py` — pulls the new cells in.
3. `python docs/sessions-learning/mine_patterns.py` — recomputes the patterns.
4. Read `PATTERNS.md`, add the new finding + action to `LEARNINGS.md`.
5. Make the smallest rule/instruction/tool change the pattern justifies, re-run, repeat.

The point: never tune on a single run or on memory. Tune on `PATTERNS.md`, which spans all
124 cells, and record why in `LEARNINGS.md`.

## Reading order
1. `VERSIONS.md` — what each map variant is and how it did.
2. `LEARNINGS.md` — the patterns (P1-P9) and the changes they drove.
3. `PATTERNS.md` / `CALL_PURPOSES.md` / `TRAJECTORIES.md` — the raw mined evidence.
4. `SESSIONS_LOG.md` / `data/sessions.jsonl` — per-cell detail.
